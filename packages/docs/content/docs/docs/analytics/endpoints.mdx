
```ts title="TypeScript"
const [summary, exits, nodes, channels, all] = await Promise.all([
  oseq.analytics.summary('seq_01J9…'),
  oseq.analytics.exits('seq_01J9…'),
  oseq.analytics.nodes('seq_01J9…'),
  oseq.analytics.channels('seq_01J9…'),
  oseq.analytics.sequences({ min_enrolled: 20 }),
]);
```

</CodeGroup>

All five take `version` (a version id), `from`, `to`, `sender` and `country`; scope `read`. `from` and `to` apply to the enrollment date for `summary`, `exits` and the cross-sequence table, and to the run's creation date for `nodes` and `channels`. Rates are per 100 and rounded to one decimal; a rate with no denominator is `null`, never `NaN`.

## Summary

`GET /v1/sequences/{id}/analytics/summary`

| Field | Meaning |
|---|---|
| `enrolled` | enrollments created (in the filter) |
| `active`, `exited`, `completed` | by current status (`active` includes `paused` and `waiting_limit`) |
| `touches_delivered` | outreach runs whose message was delivered (the send time for email, which has no receipt; Allo's `sms.sent` for texts); the second denominator |
| `replies`, `meetings` | enrollments with a first reply or a first meeting |
| `reply_rate_per_100_enrolled`, `meeting_rate_per_100_enrolled` | per enrolled |
| `reply_rate_per_100_delivered`, `meeting_rate_per_100_delivered` | per delivered touch |
| `replies_by_channel` | `{ email, sms, call }` counts of attributed replies |

## Exits

`GET /v1/sequences/{id}/analytics/exits` returns `exits: [{ reason, count }]` largest first: `replied`, `meeting_booked`, `opt_out`, `bounced`, `suppressed`, `manual`, `deleted`.

## Nodes

`GET /v1/sequences/{id}/analytics/nodes` returns one row per step:

| Field | Meaning |
|---|---|
| `node_id`, `node_type`, `channel` | the step |
| `reached` | runs of this node |
| `executed` | outreach runs that were sent |
| `skipped`, `skipped_by_reason` | runs a gate refused, with `{ no_consent: 12, suppressed: 3, … }` |
| `failed` | runs that ran out of retries |
| `delivered`, `bounced` | from the run's recorded outcome |
| `replies`, `meetings` | signals attributed to this step's runs |
| `reply_rate_per_100_delivered` | |
| `median_time_to_reply_seconds` | median of reply time minus send time |

## Channels

`GET /v1/sequences/{id}/analytics/channels` returns one row per `(channel, touch_number)`: `reached`, `sent`, `skipped`, `delivered`, `bounced`, `replies`, `meetings`, `reply_rate_per_100_sent`, `meeting_rate_per_100_sent`. The touch number counts only messages actually sent (1 is the first one the contact received); a channel's skipped and failed runs share a row with `touch_number: 0`. The split is deliberate: SMS usually comes later and to warmer contacts, so an email-versus-SMS chart is only fair at the same position in the sequence. See [Comparing channels](/docs/analytics/comparing-channels).

## Cross-sequence

`GET /v1/analytics/sequences?min_enrolled=` returns `sequences: [{ sequence, name, status, enrolled, replies, meetings, replies_per_100_enrolled, meetings_per_100_enrolled }]`, every sequence of the project ranked by replies then meetings per 100 enrolled; `min_enrolled` hides tiny samples. It has no status counts: for a list screen that also shows running and finished, read `counts` from [`GET /v1/sequences`](/docs/sequences/versions#reading) (active, paused, waiting_limit, completed, exited, failed per sequence, in the same page) and join the two on the sequence id. Neither call is per sequence, so a list screen costs one analytics call plus one page of sequences, not one request per row.

<Note>The architecture document also lists `GET /v1/analytics/channels` (all sequences compared by channel) and a 60-second cache. Neither exists in the code today.</Note>

## What a client can show

| Screen | Numbers | Endpoint |
|---|---|---|
| Sequence overview | replies and meetings (rate vs enrolled and delivered), replies by channel, exit reasons | `summary`, `exits` |
| Per step | reached, executed, skipped by reason, failed, delivered, bounced, replies, meetings, median time to reply | `nodes` |
| Channel comparison | per channel and touch number | `channels` |
| By version | any of the above with `?version=` | |
| Cross-sequence | sequences ranked by replies and meetings per 100 enrolled | `/v1/analytics/sequences` |
