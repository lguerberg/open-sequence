OpenSequence sends from real people's mailboxes and phone numbers and reads their replies, so this page lists every control that protects that access. To harden a deployment, read [Security hardening](/docs/self-hosting/security-hardening); to report a vulnerability privately, see [Support](/docs/community/support).

## Controls

| Concern | Control |
|---|---|
| Operator and projects | `SEQ_ADMIN_TOKEN` protects `/v1/admin/*` only and is compared in constant time. Project API keys protect everything else and never reach another project's data |
| Authentication | keys are `sk_live_…` with 256 bits of entropy, stored as SHA-256 hashes, shown once, revocable, with `last_used_at`. Each key resolves to one project; every query filters on `project_id`; another project's ids answer `404` |
| Scopes | `read` < `enroll` < `admin`. An `enroll` key cannot publish or edit a sequence, or grant SMS consent |
| Secrets at rest | the Google client secret, each sender's refresh token, the Allo and Attio keys and webhook signing secrets are AES-256-GCM under `SEQ_ENCRYPTION_KEYS`, and write-only: no endpoint returns them. Responses show status, key id, the last four characters and timestamps. Known secret fields are redacted from logs |
| Google OAuth | the project's own OAuth client. The `state` is signed, valid for ten minutes and bound to the sender and connection. Disconnecting revokes the grant at Google. Only the auth module touches tokens |
| Mailbox privacy | the service reads only threads it started in the last 30 days. Reply bodies are stored only when `store_inbound_bodies` is on (default off). From the calendar it keeps only the event id, start time and the matched attendee, for events with an enrolled attendee |
| Inbound webhooks | Allo: Standard Webhooks signature with the secret Allo issued, timestamps within 5 minutes, idempotent by event id. Google push: acknowledged only; polling is the source of truth |
| Outbound webhooks | Standard Webhooks signatures, HTTPS only, public addresses only (resolved again at every attempt), no redirects, 10-second timeout |
| Do not contact | suppressions from your reports, unsubscribe clicks, STOP texts, bounces and complaints, checked at enrollment and again just before each send |
| SMS | consent defaults to false and only an `admin` key can set it, with a `source` and a time. No text without consent, a known recipient time zone, 08:00 to 21:00 recipient time, and a country on the project's `sms_countries` list (default `["US"]`) |
| Unsubscribe | always exits the sequence (not configurable) and suppresses the channel. Emails carry `List-Unsubscribe` and `List-Unsubscribe-Post` (one click). Links are signed and valid for 90 days |
| Data in runs | the facts a condition read and the values a template rendered are stored at decision time. Erase a person with `DELETE /v1/contacts/{id}`: see [Data retention](/docs/security/data-retention) |
| Audit | every enrollment records `enrolled_by` and its kind; every exit records its reason and signal; flag changes record the key that made them |
| Input limits | definitions up to 256 KB and 200 nodes; Zod validation on every body; contact batches up to 500; 600 requests a minute per key; bodies up to 2 MB |
| Dependencies | Postgres 14 or newer with no extensions; Node 22; Redis only when `SEQ_QUEUE=redis` |

## What the service never does

- It never calls your application except at the webhook endpoints you registered.
- It never reads your database.
- It never sends from an address a sender did not connect.
- It never texts without consent.
- It never reads mail outside its own threads.
- It never returns a secret it stored.
- It never writes to your CRM: the CRM connection is read-only.

## Known gaps

| Gap | Today |
|---|---|
| `Idempotency-Key` header | not supported; retry a create only after checking whether it happened |
| `/metrics` endpoint | none; use the health endpoints and logs ([Observability](/docs/self-hosting/observability)) |
| `X-Request-Id` | not propagated; the service makes its own `req_…` id |
| `retention_days` | accepted, not enforced ([Data retention](/docs/security/data-retention)) |
| rate limit | counted per api replica, not globally |
| key rotation | no command re-encrypts stored secrets under a new key yet ([Security hardening](/docs/self-hosting/security-hardening)) |

See the [roadmap](/docs/community/roadmap).
