---
title: "Contacts"
description: "Upsert one or many contacts by your own id, with email, phone, time zone and free attrs; read, list and erase them."
---

<CodeGroup>

```bash title="curl"
curl -X PUT $SEQ/v1/contacts/p_7 -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" -d '{
  "first_name": "Dana", "last_name": "Whitfield", "email": "dana@example.com",
  "phone": "+447700900123", "country": "GB", "timezone": "Europe/London",
  "attrs": { "company": { "name": "Example Ltd", "country": "UK" }, "deal": { "stage": "contacting" } }
}'
```

```ts title="TypeScript"
await oseq.contacts.upsert('p_7', {
  first_name: 'Dana',
  last_name: 'Whitfield',
  email: 'dana@example.com',
  phone: '+447700900123',
  country: 'GB',
  timezone: 'Europe/London',
  attrs: { company: { name: 'Example Ltd', country: 'UK' }, deal: { stage: 'contacting' } },
});
```

</CodeGroup>

`PUT /v1/contacts/{external_id}` creates or updates. Scope `enroll`. Every field is optional and nullable (`null` clears it); `attrs` is **merged by top-level key** into the existing attrs, so an upsert that sends `{ "attrs": { "deal": { "stage": "won" } } }` keeps `attrs.company` but replaces the whole `attrs.deal` object (see [Attributes](/docs/contacts/attrs)).

| Field | Rules |
|---|---|
| `email` | a valid address, up to 320 characters; required for email steps and for CRM lookups |
| `phone` | E.164 (`+14155551234`), normalized on input; an invalid number is `422 INVALID_CONTACT` |
| `country` | ISO 3166-1 alpha-2, upper-cased; checked against `settings.sms_countries` before a text. Anything other than two letters is `400 VALIDATION_ERROR`; a two-letter value that is not a real code is stored as is (there is no ISO list check), so map country names to codes on your side and omit the field when you have no code |
| `timezone` | an IANA zone. Used for send windows, business days and SMS quiet hours; when absent the service infers one from the phone's area code and country for SMS, and falls back to the sender's zone for windows |
| `attrs` | any JSON object; see [Attributes](/docs/contacts/attrs) |

`sms_consent` is not in this body: it has its own admin-only endpoint ([Consent](/docs/contacts/consent-and-suppressions)).

## Batch upsert

<CodeGroup>

```bash title="curl"
curl -X POST $SEQ/v1/contacts:batch -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"contacts":[{"external_id":"p_7","email":"dana@example.com"},{"external_id":"p_8","email":"tom@example.com","timezone":"Europe/Berlin"}]}'
```

```ts title="TypeScript"
const contacts = await oseq.contacts.batch([
  { external_id: 'p_7', email: 'dana@example.com' },
  { external_id: 'p_8', email: 'tom@example.com', timezone: 'Europe/Berlin' },
]);
```

</CodeGroup>

Up to 500 per call (`422 BATCH_TOO_LARGE`), same semantics as `PUT`, returns the contacts in order. Enrolling also accepts inline contacts (`{ external_id, ...fields }`) and upserts them first.

## Patch

`PATCH /v1/contacts/{id}` takes the same body and is how you keep `attrs` fresh for conditions: the service never reads your database, so a changed deal stage reaches a condition only if you send it.

## Read, status, list, timeline

<CodeGroup>

```bash title="curl"
curl $SEQ/v1/contacts/p_7 -H "Authorization: Bearer $KEY"           # the contact + suppressions + the active enrollment or null
curl -X POST $SEQ/v1/contacts:status -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" -d '{"ids":["p_7","p_8","ctc_01J9…"]}'
curl "$SEQ/v1/contacts?email=dana@example.com" -H "Authorization: Bearer $KEY"
curl $SEQ/v1/contacts/p_7/timeline -H "Authorization: Bearer $KEY"  # messages in and out, signals, tasks, newest first
```

```ts title="TypeScript"
const contact = await oseq.contacts.get('p_7');
const statuses = await oseq.contacts.statuses(['p_7', 'p_8']); // [{ contact: { id, external_id }, enrollment: { id, sequenceId, versionId, senderId, status, currentNodeId } | null }]
const { items } = await oseq.contacts.list({ email: 'dana@example.com' });
const timeline = await oseq.contacts.timeline('p_7'); // [{ kind: 'message' | 'signal' | 'task', at, item }]
```

</CodeGroup>

`POST /v1/contacts:status` (scope `read`, up to 500 ids or external ids) returns each contact's active enrollment or `null`, for "in a sequence" badges in a list. `GET /v1/contacts` filters by `email`, `external_id` and `updated_since`, paginated. The timeline merges the last 200 messages, 200 signals and 200 tasks.

## Erase

<CodeGroup>

```bash title="curl"
curl -X DELETE $SEQ/v1/contacts/p_7 -H "Authorization: Bearer $KEY"
```

```ts title="TypeScript"
await oseq.contacts.delete('p_7');
```

</CodeGroup>

Scope `admin`. Active enrollments exit first with reason `deleted` (an `enrollment.exited` is delivered), then the contact and everything attached (messages, tasks, runs, signals, suppressions) are deleted. Counts already in analytics stay. Call it on a privacy request and when the person is deleted or merged in your CRM.
