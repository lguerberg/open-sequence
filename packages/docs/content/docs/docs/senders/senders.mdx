title: "Senders"
description: "Register the people who send, set their time zone and limits, read their readiness, disable them."
---

A sender is the acting user an enrollment runs as. Register one with your own id, then connect the channels they send on.

<CodeGroup>

```bash title="curl"
curl -X PUT $SEQ/v1/senders/u_42 -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"name":"Max Rivera","email":"max@acme.com","timezone":"America/New_York","attrs":{"title":"Account Executive"}}'
```

```ts title="TypeScript"
const sender = await oseq.senders.upsert('u_42', {
  name: 'Max Rivera',
  email: 'max@acme.com',
  timezone: 'America/New_York',
  attrs: { title: 'Account Executive' },
});
```

</CodeGroup>

`PUT` creates or updates (an upsert by `external_id`); the body is `{ name, email?, timezone?, attrs? }`. Scope `admin`.

| Field | Notes |
|---|---|
| `name` | required, up to 160 characters; `{{ sender.name }}` and `{{ sender.first_name }}` in templates |
| `email` | the address the Google connection is expected to use; with mock providers it becomes the mailbox |
| `timezone` | an IANA zone, default `UTC`. Tasks are due and expire on the sender's calendar; a send window with `tz: "sender"` follows it; business-day math for a contact without a zone falls back to it |
| `attrs` | free JSON; `{{ sender.attrs.<path> }}` in templates, `sender.attrs.<path>` in conditions |

## Channels

A sender sends through channels; each one is created by its own call and has its own status and limits.

| Channel | How it is created | Provider |
|---|---|---|
| `email` | `POST /v1/senders/{id}/connections/google` and the sender's consent ([Connect Google](/docs/senders/connect-google)) | the sender's own Gmail and Calendar, through your project's OAuth client |
| `sms` | `PUT /v1/senders/{id}/channels/sms` with an Allo user and number ([Connect Allo](/docs/senders/connect-allo)) | the project's Allo key |

Statuses: `pending`, `active`, `paused`, `credentials_needed`, `restricted`, `disconnected`. Only `active` channels send; a step on any other status is skipped with `sender_channel_<status>`, and `credentials_needed` additionally pauses the step and raises `sender.channel_status` so you can ask the user to reconnect.

### Limits

<CodeGroup>

```bash title="curl"
curl -X PATCH $SEQ/v1/senders/u_42/channels/email -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"daily_limit":50,"min_gap_seconds":90}'
```

```ts title="TypeScript"
await oseq.senders.patchChannel('u_42', 'email', { daily_limit: 50, min_gap_seconds: 90 });
```

</CodeGroup>

| Field | Default (email / sms) | Meaning |
|---|---|---|
| `daily_limit` | 30 / 100 | sends in a rolling 24 hours; over it the step is deferred for an hour and the enrollment shows `waiting_limit`. `null` removes the cap |
| `weekly_limit` | none | stored for the channel; not enforced by the executors yet |
| `min_gap_seconds` | 60 / 0 | the minimum time between two sends on the channel; a step inside the gap is deferred to the end of it |
| `opted_in` | | sets `opted_in_at`, the sender's written acknowledgement for the channel; stored, not enforced |
| `status` | `active` | `paused` stops the channel without removing it |

Deferrals are per sender and channel, so a batch of 5,000 enrollments never fires at once: the enrollment preview staggers first touches by the sender's daily email capacity (`capacity.per_day`, `days_to_first_touches`).

## Readiness

Before enrolling, ask which steps a sender can run and why not.

<CodeGroup>

```bash title="curl"
curl $SEQ/v1/senders/u_42/readiness -H "Authorization: Bearer $KEY"
# {"email":{"ok":true},"sms":{"ok":false,"reason":"no_allo_number"},"task":{"ok":true}}
```

```ts title="TypeScript"
const readiness = await oseq.senders.readiness('u_42');
if (!readiness.email.ok) console.log(readiness.email.reason); // google_not_connected, email_credentials_needed, email_disconnected, …
```

</CodeGroup>

Reasons are `google_not_connected` and `no_allo_number` when the channel does not exist, and `<channel>_<status>` (`email_credentials_needed`, `sms_paused`, …) when it exists but is not active. `GET /v1/senders/{id}` returns the sender with `channels`, `readiness` and `connections` in one call.

## Listing

`GET /v1/senders` is cursor-paginated (`limit`, `cursor`, `updated_since`). `GET /v1/senders/{id}/tasks?status=open` lists the sender's open tasks for an inbox ([Tasks](/docs/enrollments/tasks)).

## Disabling a sender

<CodeGroup>

```bash title="curl"
curl -X DELETE $SEQ/v1/senders/u_42 -H "Authorization: Bearer $KEY"
```

```ts title="TypeScript"
await oseq.senders.disable('u_42');
```

</CodeGroup>

`DELETE` disables; nothing is deleted. New enrollments as this sender are refused (`409 SENDER_DISABLED`); their steps skip from now on. `PUT` the sender again to re-enable. Removing one channel (`DELETE /v1/senders/{id}/channels/sms`) keeps the sender and makes that channel's steps skip; disconnecting Google (`DELETE /v1/senders/{id}/connections/google`) revokes the token at Google and sets the email channel `disconnected`.
