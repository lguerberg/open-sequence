title: 'Connect SMTP and IMAP'
description: 'Send from any mailbox with a password: Fastmail, Zoho, iCloud, a Google app password, Proton Bridge or your own mail server.'
---

When a sender's mailbox is not a Gmail account you can connect with Google, give the service its SMTP and IMAP settings. It sends through SMTP, files a copy in the Sent folder, and reads replies, bounces and out-of-office answers from the inbox over IMAP. Both logins are checked before anything is stored.

<CodeGroup>

```bash title="curl"
curl -X PUT $SEQ/v1/senders/u_42/channels/email -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{
    "provider": "smtp",
    "from": "max@acme.com",
    "smtp": { "host": "smtp.fastmail.com", "port": 465, "secure": true, "user": "max@acme.com", "password": "app-password" },
    "imap": { "host": "imap.fastmail.com", "port": 993, "secure": true, "user": "max@acme.com", "password": "app-password" }
  }'
# {"success":true,"data":{"channel":"email","address":"max@acme.com","status":"active","config":{"provider":"smtp",…},…}}
```

```ts title="TypeScript"
const channel = await oseq.senders.setSmtp('u_42', {
  provider: 'smtp',
  from: 'max@acme.com',
  smtp: {
    host: 'smtp.fastmail.com',
    port: 465,
    secure: true,
    user: 'max@acme.com',
    password: process.env.MAILBOX_APP_PASSWORD!,
  },
  imap: {
    host: 'imap.fastmail.com',
    port: 993,
    secure: true,
    user: 'max@acme.com',
    password: process.env.MAILBOX_APP_PASSWORD!,
  },
});
// channel.status === 'active'
```

</CodeGroup>

Scope `admin`. The call replaces the sender's email channel, whatever it was before, and returns it.

## The fields

| Field                    | Notes                                                                                                                                                                            |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `provider`               | always `"smtp"`                                                                                                                                                                  |
| `from`                   | the address mail goes out from. Optional: it defaults to the SMTP `user` when that is an address, else to the sender's `email`                                                   |
| `smtp.host`, `imap.host` | the server names, like `smtp.fastmail.com` and `imap.fastmail.com`                                                                                                               |
| `port`                   | SMTP: `465` with `secure: true`, or `587` with `secure: false`. IMAP: `993` with `secure: true`, or `143` with `secure: false`                                                   |
| `secure`                 | `true` means TLS from the first byte. `false` means STARTTLS, which is required for every host except `localhost` and `127.0.0.1`: a password never crosses the network in clear |
| `user`                   | the login, usually the full mailbox address                                                                                                                                      |
| `password`               | write-only. Use an app password wherever the provider offers one                                                                                                                 |

## What happens when you call it

<Steps>
<Step title="Both logins are checked">

The service connects to the SMTP server and authenticates, then logs in to IMAP. If either fails, nothing is stored and the answer is a `422` naming the side and the reason, with the server's own sentence in `message`.

| Code                                   | Meaning                                                                                                                          |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `SMTP_AUTH_FAILED`, `IMAP_AUTH_FAILED` | the server refused the user or the password. Check for an app password and that IMAP or SMTP access is turned on for the mailbox |
| `SMTP_UNREACHABLE`, `IMAP_UNREACHABLE` | no connection: wrong host or port, a firewall, or a certificate the service does not trust                                       |
| `SMTP_REFUSED`, `IMAP_REFUSED`         | connected and then refused for another reason, such as STARTTLS not offered on a remote host                                     |
| `FROM_REQUIRED`                        | no `from`, the SMTP user is not an address and the sender has no `email`                                                         |

</Step>
<Step title="The settings are stored encrypted">

The passwords are encrypted under `SEQ_ENCRYPTION_KEYS`, like every other secret, and are never returned or logged. Hosts, ports and user names are kept in plain text and appear under `connections` in `GET /v1/senders/{id}` (provider `smtp`). Calling the endpoint again replaces the settings, for example after a password change.

</Step>
<Step title="The email channel is active">

The sender's `email` channel is set to the `from` address with status `active`, and `readiness.email.ok` is true. Limits, pausing and the rest of the channel work exactly as for Gmail ([Senders](/docs/senders/senders)).

</Step>
</Steps>

## Sending

Each email goes out through the sender's SMTP server with the service's own `Message-ID`, `In-Reply-To` and `References` for follow-ups in the same thread, the `List-Unsubscribe` headers, and a plain-text and an HTML part when the step is HTML. A copy is then filed in the Sent folder over IMAP: the folder the server marks as Sent, else one named `Sent`, created when there is none. When the server has already filed the message itself (Gmail does), no second copy is added. If filing the copy fails, the send still counts, so a retry never sends the email twice.

After a crash in the middle of a step, the service searches Sent, then the inbox, for the `Message-ID` before sending again.

## Reading replies

Every minute the service reads new inbox messages by IMAP UID from where it stopped, and keeps only messages that point at an email it sent in the last 30 days through `In-Reply-To` or `References`. Everything else in the mailbox is ignored and never stored.

| Message                                                                                                        | Becomes                                                        |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| an answer in one of the sequence's threads                                                                     | a `reply` signal                                               |
| a delivery status report (RFC 3464) naming one of the service's `Message-ID`s                                  | a `bounce` signal: hard for a `5.x.x` status, soft for `4.x.x` |
| an answer marked `Auto-Submitted`, `X-Autoreply` or `Precedence: auto_reply`, or with an out-of-office subject | an `ooo` signal, with the return date when the text names one  |

Reply bodies are stored only when the project sets `store_inbound_bodies: true`. Every 15 minutes the service also logs in to both servers. A refused login sets the channel `credentials_needed`, the sender's email steps wait, and `sender.channel_status` is delivered to your endpoints: call the endpoint again with the new password. An SMTP mailbox has no calendar, so meeting detection from Google Calendar does not run for this sender.

## Provider notes

| Provider                  | SMTP                                                  | IMAP                                            | Notes                                                                                                                                                                                                                                                                                           |
| ------------------------- | ----------------------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Google Workspace or Gmail | `smtp.gmail.com`, `465`, secure                       | `imap.gmail.com`, `993`, secure                 | needs 2-Step Verification and an [app password](https://support.google.com/accounts/answer/185833). A Workspace admin can turn app passwords off. [Connect Google](/docs/senders/connect-google) is the better choice when you can register an OAuth client: it adds Calendar                   |
| Fastmail                  | `smtp.fastmail.com`, `465`, secure                    | `imap.fastmail.com`, `993`, secure              | create an app password with IMAP and SMTP access in Settings, Privacy and Security                                                                                                                                                                                                              |
| Zoho Mail                 | `smtp.zoho.com`, `465`, secure                        | `imap.zoho.com`, `993`, secure                  | organization accounts use `smtppro.zoho.com` and `imappro.zoho.com`, and data centers outside the US use their own domain (`.eu`, `.in`, `.com.au`). Turn on IMAP access in Zoho Mail settings, and use an app-specific password when two-factor sign-in is on                                  |
| iCloud Mail               | `smtp.mail.me.com`, `587`, STARTTLS (`secure: false`) | `imap.mail.me.com`, `993`, secure               | needs an [app-specific password](https://support.apple.com/en-us/102654). The SMTP user is the full iCloud address; for IMAP try the part before the `@` if the full address is refused                                                                                                         |
| Proton Mail               | `127.0.0.1`, `1025`, STARTTLS (`secure: false`)       | `127.0.0.1`, `1143`, STARTTLS (`secure: false`) | through Proton Mail Bridge, which must run on the same machine as the service. Use the user and password Bridge shows, not your Proton password. Bridge's certificate is self-signed: export it from Bridge's advanced settings and start the service with `NODE_EXTRA_CA_CERTS` pointing at it |
| Your own server           | your host                                             | your host                                       | any server with SMTP AUTH and IMAP works. For a private certificate authority, set `NODE_EXTRA_CA_CERTS`                                                                                                                                                                                        |

<Warning>
  Microsoft 365, Exchange Online and Outlook.com are not supported by this adapter. Microsoft has
  retired password sign-in for IMAP and SMTP and requires OAuth, which this adapter does not do. A
  Microsoft mailbox needs its own adapter.
</Warning>

## Removing the mailbox

<CodeGroup>

```bash title="curl"
curl -X DELETE $SEQ/v1/senders/u_42/channels/email -H "Authorization: Bearer $KEY"
```

```ts title="TypeScript"
await oseq.senders.deleteChannel('u_42', 'email');
```

</CodeGroup>

The channel is removed, the stored passwords are deleted, and the connection shows `disconnected`. The sender's email steps skip from then on. Disconnecting Google (`DELETE /v1/senders/{id}/connections/google`) does not touch an SMTP channel, and connecting Google afterwards moves the sender back to Gmail.

## With mock providers

`SEQ_DEV_MOCK_PROVIDERS=1` skips the login check: any settings are accepted and stored, and mail goes to the mock outbox like every other email.
