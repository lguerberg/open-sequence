```bash
git clone https://github.com/lguerberg/open-sequence && cd open-sequence
pnpm install
scripts/test-db.sh start      # a throwaway Postgres on port 54329, for the integration tests
pnpm build                    # packages resolve each other through dist/
pnpm typecheck && pnpm lint && pnpm test
pnpm dev                      # the server, SEQ_ROLES=all
pnpm oseq -- --help           # the CLI
pnpm --filter @opensequence/docs dev   # these docs
```

Node 22 and pnpm 10. The repository is a pnpm workspace; `docs/ARCHITECTURE.md` is the design and `CLAUDE.md` the working rules. Where the design and the code disagree, the code is right.

`pnpm dev` reads its configuration from the process environment only, not from a file. Export the variables of `.env.example` first (it sets `SEQ_DEV_MOCK_PROVIDERS=1`, so no real provider is called) and point `SEQ_DB_DSN` at a Postgres.

## Layout

| Package | What |
|---|---|
| `packages/core` | the pure domain: the definition schema, validation, templates, conditions, timing, the interpreter and every port interface. No I/O, no package imports |
| `packages/engine` | entities, use cases (one file each) and the Drizzle persistence of the `seq` schema |
| `packages/queue` | the queue port: `postgres`, `redis`, `memory` |
| `packages/providers` | `google`, `allo`, `attio` and `mock`, registered by name |
| `packages/auth` | provider credentials and the token lifecycle (the `auth` schema); destined for its own repository |
| `packages/sdk` | `@opensequence/sdk`, types generated from the OpenAPI file |
| `packages/mcp` | `@opensequence/mcp`, the MCP server over the SDK ([MCP server](/sdks/mcp)) |
| `packages/docs` | this site |
| `apps/server` | the Fastify API, the workers, the composition root, the `oseq` CLI, `openapi.json` |
| `apps/site` | the landing page and the blog |

`engine` and `auth` are split into `src/domain`, `src/application` and `src/infrastructure`; `core` is all domain. Dependencies point inward only, and `pnpm lint` enforces it with `eslint-plugin-boundaries`: `domain` imports only `domain`, `application` imports `domain` and `application`, and neither imports `infrastructure`. A violation is a lint error, not a review comment. The other rules are kept in review: `core` imports no I/O package and no workspace package; `queue`, `providers` and `auth` never import `engine`; the SDK imports nothing from the repository.

## Tests

`pnpm test` runs Vitest across every package. Core tests are pure. Engine integration tests and the server's quickstart test need a throwaway Postgres: `scripts/test-db.sh` starts one on port 54329, or set `SEQ_TEST_DB_DSN`. Provider tests use recorded fixtures (`msw`); the `mock` provider runs everything else. CI (`.github/workflows/ci.yml`) runs build, typecheck, lint and test against a Postgres service, checks that `apps/server/openapi.json` matches the routes (`pnpm --filter @opensequence/server openapi`), and builds the Docker image.

## Conventions

TypeScript strict, ESM. Zod 4 for every boundary; Fastify with the Zod type provider so the routes **are** the OpenAPI file. Prefixed ULID ids; `project_id` on every tenant-owned table. Drizzle for all persistence, migrations generated with `pnpm db:generate` and applied by the server at boot. Registries, not switch statements: channels, node types, fact sources, providers and events are registered by name ([Extending](/docs/community/extending)). Plain-English error messages with a stable `code`. Secrets are write-only.

## Sending a change

Open a pull request against `main` with the tests that prove it; CI must be green. A change to a route regenerates `openapi.json` (commit it); a change to the env schema, the registries, the event list or the error codes regenerates these docs' reference pages at build (`pnpm --filter @opensequence/docs generate`), so nothing to commit there.
