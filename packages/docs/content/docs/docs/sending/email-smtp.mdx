This page connects a sender's mailbox. The service sends through their SMTP server and reads their IMAP inbox, and sequences use it as the sender's `email` channel. Any mailbox with SMTP and IMAP works: Gmail and Google Workspace, Fastmail, Zoho, iCloud, Proton, a company server.

<CodeGroup>

```bash title="curl"
curl -X PUT $SEQ/v1/senders/u_42/channels/email -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" -d '{
  "provider": "smtp",
  "from": "max@acme.com",
  "smtp": { "host": "smtp.fastmail.com", "port": 465, "secure": true, "user": "max@acme.com", "password": "app-password" },
  "imap": { "host": "imap.fastmail.com", "port": 993, "secure": true, "user": "max@acme.com", "password": "app-password" }
}'
# {"success":true,"data":{"channel":"email","address":"max@acme.com","status":"active","connectionId":"con_…","config":{"provider":"smtp","imap_cursor":null},…}}
```

```ts title="TypeScript"
const channel = await oseq.senders.setSmtp('u_42', {
  provider: 'smtp',
  from: 'max@acme.com',
  smtp: { host: 'smtp.fastmail.com', port: 465, secure: true, user: 'max@acme.com', password: process.env.MAX_APP_PASSWORD! },
  imap: { host: 'imap.fastmail.com', port: 993, secure: true, user: 'max@acme.com', password: process.env.MAX_APP_PASSWORD! },
});
```

</CodeGroup>

`PUT /v1/senders/{id}/channels/email` needs an `admin` key and returns the email channel. It replaces any email channel the sender had. Saving again (a new password, say) updates the same connection, keeps the limits and sets the channel `active`. A missing `imap` or an unknown field is a `400`.

| Field | Notes |
|---|---|
| `provider` | Always `"smtp"`. |
| `from` | Optional, stored in lower case. Defaults to `smtp.user` when that is an address, else the sender's `email`. |
| `smtp`, `imap` | Both required. Each has `host`, `port`, `secure`, `user` and `password`. |
| `secure` | `true`: TLS from the first byte (SMTP 465, IMAP 993). `false`: STARTTLS (SMTP 587, IMAP 143), required except on a loopback host (`localhost`, `127.x.x.x`, `::1`), so a password never crosses the network in clear. |
| `user` | The login, usually the full mailbox address. |
| `password` | Write-only. Use an app password wherever the provider offers one. |

<Warning>Microsoft 365, Exchange Online and Outlook.com cannot connect this way: Microsoft has retired password sign-in for SMTP and IMAP. There is no Microsoft connector yet.</Warning>

## Gmail and Google Workspace

1. Turn on 2-Step Verification for the Google account.
2. Create an app password at [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) and use it as both passwords.
3. Use `smtp.gmail.com`, port 465, and `imap.gmail.com`, port 993, both with `secure: true`. The user is the full address.

A Workspace admin can block app passwords. If the page says the setting is not available, ask the admin to allow them.

Google limits how much one mailbox sends: about 2,000 messages a day on Workspace and about 500 on a free Gmail account. Keep the channel's `daily_limit` well under that (the default is 30).

## Verified on save

Before anything is stored, the service signs in to the SMTP server, then to IMAP. The first failure answers `422`, nothing is saved, and `message` quotes the server's own words, never the password.

| Code | Meaning |
|---|---|
| `SMTP_AUTH_FAILED`, `IMAP_AUTH_FAILED` | The server refused the user or password. Use an app password and check that SMTP or IMAP access is on. |
| `SMTP_UNREACHABLE`, `IMAP_UNREACHABLE` | No connection: wrong host or port, a firewall, a timeout, or a certificate the service does not trust. |
| `SMTP_REFUSED`, `IMAP_REFUSED` | Connected, then refused for another reason, such as no STARTTLS on a remote host. |
| `FROM_REQUIRED` | No `from`, the SMTP user is not an address and the sender has no `email`. |

With `SEQ_DEV_MOCK_PROVIDERS=1` the logins are not checked: any settings are stored, and mail goes to the mock outbox.

## Where the settings live

Both passwords are encrypted under `SEQ_ENCRYPTION_KEYS` and never returned or logged. The rest is plain config on the sender's `smtp` connection, shown by `GET /v1/senders/{id}/connections` and in `GET /v1/senders/{id}`:

```json
{ "id": "con_…", "provider": "smtp", "account": "max@acme.com", "status": "active",
  "config": {
    "smtp": { "host": "smtp.fastmail.com", "port": 465, "secure": true, "user": "max@acme.com" },
    "imap": { "host": "imap.fastmail.com", "port": 993, "secure": true, "user": "max@acme.com" } } }
```

## Provider settings

| Mailbox | SMTP | IMAP | Notes |
|---|---|---|---|
| Gmail or Google Workspace | `smtp.gmail.com`, 465, `secure: true` | `imap.gmail.com`, 993, `secure: true` | Needs 2-Step Verification and an app password. See [Gmail and Google Workspace](#gmail-and-google-workspace). |
| Fastmail | `smtp.fastmail.com`, 465, `secure: true` | `imap.fastmail.com`, 993, `secure: true` | An app password with IMAP and SMTP access. |
| Zoho Mail | `smtp.zoho.com`, 465, `secure: true` | `imap.zoho.com`, 993, `secure: true` | Organization accounts use `smtppro.zoho.com` and `imappro.zoho.com`; other regions use their own domain (`.eu`, `.in`). Turn on IMAP access. |
| iCloud Mail | `smtp.mail.me.com`, 587, `secure: false` | `imap.mail.me.com`, 993, `secure: true` | An app-specific password. If IMAP refuses the full address, try the part before the `@`. |
| Proton Mail | `127.0.0.1`, 1025, `secure: false` | `127.0.0.1`, 1143, `secure: false` | Through Proton Mail Bridge on the service's host, with the login Bridge shows. Export Bridge's self-signed certificate and point `NODE_EXTRA_CA_CERTS` at it. |
| Your own server | your host | your host | Any server with SMTP AUTH and IMAP. For a private certificate authority, set `NODE_EXTRA_CA_CERTS`. |

## Sending

An email step passes the gates and limits every channel has ([Channels](/docs/sending/channels#gates-every-send-passes)) and gets `List-Unsubscribe` headers. It leaves through the SMTP server with a `Message-ID` the service sets; `reply_in_thread: true` adds `In-Reply-To` and `References`.

SMTP keeps no copy, so the service files one, marked read, in the folder the server flags as Sent, else one named Sent, Sent Items, Sent Mail or Sent Messages, else a new `Sent`. A copy the server already filed (Gmail does) is not filed twice. A failure to file is logged and does not fail the step.

If a send crashes halfway, the retry searches Sent, then the inbox, for that `Message-ID`, and marks the step sent without sending again when it is there.

## Replies, auto-replies and bounces

Every minute, the poll job opens the IMAP **inbox** read-only and reads new messages by UID from the channel's `imap_cursor`. Other folders are never read. The first poll only records the inbox's current end, so older mail is never read; the same happens if the server renumbers the mailbox (a new UIDVALIDITY). A busy inbox is read 200 messages at a time.

A message is kept only if its `In-Reply-To` or `References` names an email or thread the service sent from this mailbox in the last 30 days. Everything else is skipped and never stored, and so is mail from the sender's own address.

| What arrived | How it is recognised | Effect |
|---|---|---|
| Reply | names one of our emails | a `reply` signal: it wakes a `wait_for`, and exits the enrollment when `exit_on` lists `reply` |
| Auto-reply | an `Auto-Submitted`, `X-Autoreply`, `X-Autorespond` or `Precedence: auto_reply` header, or a subject such as "Automatic reply" or "Out of office" | pauses the enrollment until the return date it mentions, or for seven days |
| Bounce | from `mailer-daemon` or `postmaster`, or carrying a delivery status report, naming one of our emails | a 4.x.x status is soft and changes nothing; anything else is hard: email is suppressed for the contact and the enrollment exits with `bounced` |

Reply bodies are not fetched today, whatever `store_inbound_bodies` says; only an auto-reply's text is read, to find the return date. The service does not read calendars, so it never sees a meeting. Report one with `POST /v1/contacts/{id}/events` and `{ "id": "…", "type": "meeting_booked" }` ([Contact events](/docs/contacts/events)).

## Health

Every 15 minutes, after a successful poll, the service signs in to IMAP and SMTP again:

| Result | Channel status |
|---|---|
| Both work | `active` |
| A login is refused | `credentials_needed` |
| A server cannot be reached | unchanged; the next check decides |
| Something else is refused | `restricted` |

A change made by this check raises `sender.channel_status`. A login refused during a send also sets `credentials_needed` and defers the step an hour, without the webhook, so watch readiness too. While the channel is not `active`, email steps skip and the inbox is not polled. Save working settings again to bring it back.

## Removing

<CodeGroup>

```bash title="curl"
curl -X DELETE $SEQ/v1/senders/u_42/channels/email -H "Authorization: Bearer $KEY"
```

```ts title="TypeScript"
await oseq.senders.deleteChannel('u_42', 'email');
```

</CodeGroup>

This removes the email channel, deletes the passwords and marks the `smtp` connection `disconnected`; email steps skip from then on. To stop for a while, `PATCH` the channel with `{ "status": "paused" }`.

Saving new settings, for another mailbox or a new password, restarts the IMAP cursor at the inbox's current end.
