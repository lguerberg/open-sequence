```text
Quick question, {{ contact.first_name | "there" }}

Hi {{ contact.first_name | "there" }}, {{ sender.first_name }} here from {{ sender.attrs.company | "Acme" }}.
I saw {{ attrs.company.name | "your company" }} is hiring. Worth a chat about {{ sequence.name }}?

Unsubscribe: {{ unsubscribe_url }}
```

Subjects, bodies, task titles, bodies and links are rendered by one small engine. The syntax is `{{ path }}` and `{{ path | "fallback" }}`. Nothing else: no logic, no loops, no filters, no code.

## Paths

| Path | Value |
|---|---|
| `contact.first_name`, `contact.last_name`, `contact.email`, `contact.phone`, `contact.country`, `contact.timezone` | the contact's columns |
| `attrs.<path>` | the contact's attrs (`contact.attrs.<path>` is accepted as an alias) |
| `sender.name`, `sender.first_name`, `sender.email`, `sender.timezone` | the sender's columns |
| `sender.attrs.<path>` | the sender's attrs |
| `sender.signature` | the sender's signature: the sanitized HTML in an html body, the text twin in a text body. The only path rendered without escaping ([Senders](/docs/sending/senders)) |
| `sequence.name` | the sequence's name |
| `unsubscribe_url` | the opt-out link for this run: your own page when the project sets `unsubscribe_url`, else the page this server hosts |

A path outside these roots is a publish error (`BAD_TEMPLATE`).

## The signature

Store each sender's signature once (`PUT /v1/senders/{id}` with `signature_html`, and `signature_text` if the derived text is not what you want) and end the body with `{{ sender.signature }}`. One template then serves every sender:

```json
"body": "Hi {{ contact.first_name | \"there\" }},<p>Welcome aboard.</p>{{ sender.signature }}<p>{{ unsubscribe_url }}</p>",
"format": "html"
```

The HTML is sanitized when saved with an email allowlist: table layouts, inline styles, links (`http`, `https`, `mailto`, `tel`) and images over `https` or as base64 stay; scripts, forms, frames, event handlers and CSS that loads anything are dropped ([Senders](/docs/sending/senders#the-signature)). An empty signature renders as nothing, or as the fallback when you give one.

## Missing values and fallbacks

A missing or empty value renders as the fallback, or as an empty string when there is none, and never throws. Three paths **must** carry a fallback to publish, because they are empty for some contacts: `contact.first_name`, `contact.last_name`, `contact.email` (`BAD_TEMPLATE`: "can be empty for some contacts. Give it a fallback"). Everything else may be empty. A fallback is a double-quoted string; escape a quote inside it with a backslash.

## Text and HTML

Email bodies are `text` (default) or `html` (`params.format`). In `html`, every rendered value is HTML-escaped, and the message carries a plain-text alternative made from the HTML: one line per block, links as `label (url)`, images as `[alt]`. In `text`, values are inserted as is. SMS bodies and task fields are plain text.

A text body holds up to 100,000 characters and an html body up to 5,000,000, enough for a branded layout with a few embedded images.

## HTML emails and images

An `html` body is sent as you wrote it. Write it the way email builders such as Customer.io or Mailchimp do: tables for layout, inline `style` attributes, widths in pixels. The body is written by your project's admins, so the service does not sanitize it; only signatures, which any rep can edit, go through the allowlist.

An image can be hosted or embedded.

- **Hosted**: `<img src="https://cdn.example.com/logo.png">`. The email stays small, and the client loads the image when the reader opens it. Hosted images are untouched at send time. They are the best choice for large campaigns and for anything above a few kilobytes.
- **Embedded**: `<img src="data:image/png;base64,...">` with a PNG, JPEG, GIF or WebP. Gmail, Outlook and Apple Mail do not show `data:` images, so at send time every embedded image becomes an inline attachment: a part of a `multipart/related` with its own `Content-ID`, and its `src` becomes `cid:...`. The same image used twice, in the body and in the signature for example, is attached once. `alt`, `width`, `height` and `style` are kept. Embedded images show without a click on "load images", and work without a CDN.

| Limit | Value | When it is broken |
|---|---|---|
| One embedded image, decoded | 1 MB | the step fails with `IMAGE_TOO_LARGE` |
| The whole message, both bodies and the encoded images | 10 MB | the step fails with `MESSAGE_TOO_LARGE` |
| Embedded images in one html body, decoded | 400 KB | the warning `HEAVY_EMAIL` on save and publish; the email still sends |

A failed step is never truncated or sent without its images: the run fails with the code in `error`, and the enrollment follows the step's `failed` transition.

Keep emails light. Every embedded byte travels with every message, large emails are clipped by Gmail above about 100 KB of HTML and are scored as bulk mail, and an email that is mostly image reads as spam. Embed a logo or an icon; host photos and banners. Always give every image an `alt`: many readers block images, and the text alternative shows `[alt]` in its place.

## The unsubscribe link

`{{ unsubscribe_url }}` renders a signed link, valid for 90 days, that writes an email suppression and exits the enrollment with one click. By default it points at a page this server hosts, `SEQ_PUBLIC_URL/u/{token}`. When the project setting `unsubscribe_url` is set, for example `https://app.example.com/u/{token}`, it renders that URL with the token in place of `{token}`, so the link is on your own domain. Every email also carries `List-Unsubscribe` and `List-Unsubscribe-Post` headers with the same URL. An email body without it publishes with the warning `NO_UNSUBSCRIBE`. See [Consent and suppressions](/docs/contacts/consent-and-suppressions#host-the-unsubscribe-page-in-your-app).

## What is recorded

Every run that rendered something stores the values it used in `result.rendered` (`{ "contact.first_name": "Dana", "attrs.company.name": null }`), so the journey shows what the contact received. Task titles and bodies are stored on the task itself.
