---
title: "CRM conditions"
description: "Connect Attio with one API key, then branch on person, company and deal facts read live when the condition runs. Read-only, no sync."
---

A condition can read the contact's person, company and open deal from Attio at the moment it runs, with no sync and nothing stale. Use it to route a contact by deal stage, company size or any CRM attribute; connect Attio once per project first.

```json
"check_deal": {
  "type": "condition",
  "params": { "mode": "all", "rules": [
    { "field": "crm.deal.exists", "op": "is_true" },
    { "field": "crm.deal.stage", "op": "is", "value": "Lead" },
    { "field": "crm.company.employee_count", "op": "is_not_empty" } ] },
  "next": { "yes": "call_1", "no": "email_2" }
}
```

## Connect Attio

<Steps>
<Step title="Create an API key in Attio">

In Attio's workspace settings, create an access token for OpenSequence with read access to records and to the object configuration (the schema endpoint reads attribute definitions). The service never writes to Attio.

</Step>
<Step title="Store it in the project">

<CodeGroup>

```bash title="curl"
curl -X PUT $SEQ/v1/project/providers/attio -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"api_key":"…"}'
```

```ts title="TypeScript"
await oseq.project.setProvider('attio', { api_key: process.env.ATTIO_KEY! });
```

</CodeGroup>

This needs an `admin` key. The service checks the token with Attio first and refuses one that is invalid or inactive with `422 INVALID_CREDENTIAL`. The token is encrypted and never returned; save it again to rotate it.

</Step>
<Step title="Load the schema for your condition picker">

<CodeGroup>

```bash title="curl"
curl $SEQ/v1/project/providers/attio/schema -H "Authorization: Bearer $KEY"
# {"objects":[{"name":"person","attributes":[{"slug":"job_title","label":"Job title","type":"text"},…]},
#             {"name":"company",…},
#             {"name":"deal","attributes":[{"slug":"stage","label":"Stage","type":"status","values":["Lead","In Progress","Won 🎉","Lost"]},…]}]}
```

```ts title="TypeScript"
const schema = await oseq.project.attioSchema();
const stage = schema.objects.find((o) => o.name === 'deal')!.attributes.find((a) => a.slug === 'stage');
```

</CodeGroup>

`GET /v1/project/providers/attio/schema` (a `read` key) lists the `person`, `company` and `deal` objects with their attributes that are not archived: `slug`, `label`, `type`, and `values` for status and select attributes. It is fetched from Attio and cached for an hour per process. Show this list under `crm.*` in your condition editor.

</Step>
</Steps>

## The lookup

Each condition step does one lookup per contact, shared by every `crm.*` rule in it:

1. the **person** whose email is the contact's email;
2. the **company** whose domain is the email's domain, or else the person's company;
3. the **deals** linked to that person or company. A deal is **open** unless its stage title starts with `closed`, `won`, `lost` or `churn` (ignoring case and emoji) or Attio marks the stage as a win. `crm.deal.count_open` counts the open ones, and one is **selected** by `settings.crm.deal_selection`:

| `deal_selection` | Selected deal |
|---|---|
| `newest_open` (default) | the most recently created open deal |
| `highest_value` | the open deal with the highest value, newest first on a tie |
| `any_open` | the oldest open deal |

Set it with `PUT /v1/project/settings` and `{ "crm": { "deal_selection": "highest_value" } }`. A contact without an email has no person and no company: every `crm.*.exists` is false and every attribute is empty.

## What you can read

| Field | Type |
|---|---|
| `crm.person.exists`, `crm.company.exists`, `crm.deal.exists` | bool: `is_true`, `is_false` |
| `crm.deal.count_open` | number: `eq`, `ne`, `gt`, `gte`, `lt`, `lte` |
| `crm.deal.stage` | text: the selected deal's stage title |
| `crm.person.<slug>`, `crm.company.<slug>`, `crm.deal.<slug>` | text: any attribute by its Attio slug |

An attribute is flattened to one value, its first current one, so an attribute with several values (several emails, several domains) gives only the first. A status or select gives its title, a name its full name, an email its address, a currency its amount, a link to another record that record's id, a location its parts joined with commas, and anything else its plain value (a date as its ISO string). Any `crm.<object>.<slug>` is treated as text, so use `is`, `is_not`, `contains`, `is_empty` and `is_not_empty`, and compare numbers as strings. Text comparisons ignore case.

## When Attio is down

If the lookup fails (Attio unreachable, rate-limited, the key revoked, or no key at all), each `crm.*` fact is recorded as empty with the error message. An empty fact matches no operator, not even `is_false` or `is_not`, so a rule on it fails and an `all` condition takes `no`. The run's facts show the error in the [journey](/docs/contacts/journey). Nothing is retried and nothing waits, so design the `no` branch as the safe default. A failed lookup is not repeated within the same step.

## Writes

The CRM side is read-only: nothing moves a deal, adds a note or changes an attribute. To update Attio, react to [webhook events](/docs/webhooks/overview) in your own code.

## With mock providers

With `SEQ_DEV_MOCK_PROVIDERS=1` there is no Attio key and nothing calls Attio. The schema endpoint returns a fixed sample schema (a deal `stage` with `Lead`, `In Progress`, `Won 🎉` and `Lost`), and every lookup finds nothing: `crm.*.exists` is false for every contact. The server has no way to load sample CRM records yet, so to try a deal-stage branch locally, turn mock providers off and use a real Attio key.
