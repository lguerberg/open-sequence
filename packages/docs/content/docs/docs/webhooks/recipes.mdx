Each recipe is one handler on one event. They share the receiver below: Express, the raw body, `verifyWebhook` from the SDK, a `2xx` once the event is stored, and the work done after the response so a slow CRM never makes the delivery time out (10 seconds).

```ts title="receiver.ts"
import express from 'express';
import { OpenSequence, verifyWebhook, WebhookVerificationError, type WebhookEvent } from '@opensequence/sdk';

export const oseq = new OpenSequence({ baseUrl: process.env.OSEQ_URL!, apiKey: process.env.OSEQ_KEY! });
const handlers: Record<string, (event: WebhookEvent) => Promise<void>> = {};
const seen = new Set<string>(); // event ids already handled; use your database here
export const on = (type: string, fn: (event: WebhookEvent) => Promise<void>) => (handlers[type] = fn);

const app = express();
app.post('/hooks/opensequence', express.raw({ type: 'application/json' }), (req, res) => {
  let event: WebhookEvent;
  try {
    event = verifyWebhook({ secret: process.env.OSEQ_WEBHOOK_SECRET!, headers: req.headers, body: req.body });
  } catch (err) {
    if (err instanceof WebhookVerificationError) return res.status(401).send(err.code);
    throw err;
  }
  if (seen.has(event.id)) return res.sendStatus(200); // a retry after a lost 2xx
  seen.add(event.id);
  res.sendStatus(200);
  handlers[event.type]?.(event).catch((err) => console.error(event.id, err));
});
app.listen(3000);
```

Register the endpoint once with the four types, and keep the secret it returns:

```ts
await oseq.webhooks.create({ url: 'https://crm.acme.com/hooks/opensequence', event_types: ['signal.received', 'run.done', 'task.created', 'task.expired'] });
```

Every event is `{ id, type, project, occurred_at, data }`. The `webhook-id` header is the same `id`, on every retry and replay. The fields inside `data` are in the [event catalogue](/reference/webhook-events).

## Move a deal when someone replies

`signal.received` fires for every processed signal. `data.signal.kind` is `reply` for an inbound email or text and `call_connected` for a connected call (the other kinds are `bounce`, `complaint`, `opt_out`, `ooo`, `task_completed`, `meeting_booked` and `contact_suppressed`); `data.contact.external_id` is the id you gave the contact, so it is also your CRM's person id. This is the one event that carries the contact; the others carry contact ids.

```ts
on('signal.received', async ({ data }) => {
  const { signal, contact } = data as { signal: { kind: string; channel: string | null; attribution: string }; contact: { external_id: string } };
  if (signal.kind !== 'reply' && signal.kind !== 'call_connected') return;
  if (signal.attribution === 'none') return; // a later reply in the same enrollment; the deal already moved
  await crm.deals.moveToStage({ personId: contact.external_id, stage: 'Replied', via: signal.channel ?? 'call' });
});
```

`attribution` is `direct` or `assisted` for the first reply of an enrollment. It is `none` for later replies, and for a reply no recent sequence touch explains. So this handler moves a deal once per sequence.

## Log the sent email in your timeline

`run.done` fires when an outreach step was sent. `data.run` is `{ id, node_id, node_type, channel, action, status, touch_number, provider, provider_ref, branch, enrollment }`: the node, the channel and the provider reference, but not the subject. The [journey](/docs/contacts/journey) has the message, and each sent message carries the `runId` of its step.

```ts
on('run.done', async (event) => {
  const { run } = event.data as { run: { id: string; enrollment: string; channel: string | null; node_id: string; touch_number: number } };
  if (run.channel !== 'email') return;
  const journey = await oseq.enrollments.get(run.enrollment);
  const message = journey.messages.find((m) => m.runId === run.id);
  await crm.timeline.add({
    personId: journey.contact.externalId,
    kind: 'email_sent',
    at: event.occurred_at,
    title: message?.subject ?? run.node_id,
    body: message?.body ?? '',
    externalId: run.id, // idempotent on a retried delivery
  });
});
```

## Mirror tasks into your CRM and complete them back

`task.created` carries the rendered task. Create the matching to-do in your CRM, and when the rep closes it there, complete the task in OpenSequence with the outcome so the sequence takes the right branch.

```ts
on('task.created', async ({ data }) => {
  const { task } = data as { task: { id: string; kind: string; title: string; body: string | null; link: string | null; due_at: string | null; contact: string; sender: string } };
  const contact = await oseq.contacts.get(task.contact);
  await crm.todos.create({
    externalId: task.id,
    personId: contact.externalId,
    title: task.title,
    notes: task.body ?? '',
    url: task.link,
    dueAt: task.due_at,
    kind: task.kind,
  });
});

on('task.expired', async ({ data }) => {
  const { task } = data as { task: string | { id: string } };
  await crm.todos.close(typeof task === 'string' ? task : task.id); // the id alone when the timer expired it, the full task when it was cancelled
});

// your CRM's own webhook, when a rep closes the to-do
crm.on('todo.closed', async (todo) => {
  await oseq.tasks.complete(todo.externalId, { outcome: todo.outcome ?? 'completed', note: todo.notes });
});
```

Completing a task that is already closed returns it unchanged, so a to-do closed on both sides is harmless. The outcome you send is matched against the node's `branches_by_outcome`; anything else takes `completed`.

## Alert Slack on a call task

A `call` task is time-sensitive: the rep should see it when it is created, not when they open the inbox.

```ts
on('task.created', async ({ data }) => {
  const { task } = data as { task: { id: string; kind: string; title: string; link: string | null; due_at: string | null; sender: string; contact: string } };
  if (task.kind !== 'call') return;
  const [sender, contact] = await Promise.all([oseq.senders.get(task.sender), oseq.contacts.get(task.contact)]);
  await slack.chat.postMessage({
    channel: slackChannelFor(sender.externalId),
    text: `${task.title}: ${contact.firstName ?? ''} ${contact.lastName ?? ''} (${contact.phone ?? 'no phone'}), due ${task.due_at ?? 'now'}${task.link ? ` ${task.link}` : ''}`,
  });
});
```

When the task is completed (by Allo after the call, or by your app), `signal.received` with `kind: "task_completed"` follows. It carries no outcome: read it from `GET /v1/tasks?contact=<id>&status=done` before posting it in the same thread.

## Testing a handler

Sign a test event yourself with `signWebhook(secret, id, timestamp, body)` from the SDK and post it to your receiver, or replay a real delivery with `POST /v1/webhooks/deliveries/{id}/replay`; the replayed delivery keeps its `webhook-id`, so your idempotency check must let a test through on purpose. See [Verifying signatures](/docs/webhooks/verifying) and [Retries and recovery](/docs/webhooks/retries-and-recovery).
