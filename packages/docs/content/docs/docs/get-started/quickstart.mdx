---
title: "Quickstart"
description: "Run OpenSequence with Docker Compose, send a first email through the mock mailbox and watch a reply end the sequence, in about ten minutes."
---

This page takes you from an empty folder to one contact who gets an email, replies, and leaves the sequence. It runs on your laptop with Docker Compose and mock providers, so you need no Google, Allo or Attio account.

You need Docker, `curl` and `jq`. Every command below runs as is, in one shell, from top to bottom.

<Steps>
<Step title="Start the stack">

```bash
git clone https://github.com/lguerberg/open-sequence && cd open-sequence
docker compose up -d
export SEQ=http://localhost:8080
curl -s $SEQ/readyz
# {"ok":true}
```

Compose starts Postgres and one OpenSequence container. The container applies the database migrations on boot, serves the API on port 8080 and runs the background workers in the same process. If `/readyz` answers `{"ok":false,...}`, wait two seconds and try again: it turns ready once the database is migrated and the scheduler has run its first job.

</Step>
<Step title="Create a project">

A project is one tenant: its own senders, contacts, sequences and keys. The operator token (`dev-admin-token` in the compose file) creates it, and the response carries the project's first `admin` key. The key is shown once, so keep it.

```bash
ADMIN_KEY=$(curl -s -X POST $SEQ/v1/admin/projects \
  -H "Authorization: Bearer dev-admin-token" -H "Content-Type: application/json" \
  -d '{"slug":"acme","name":"Acme"}' | jq -r .data.api_key)
echo $ADMIN_KEY
# sk_live_...
```

</Step>
<Step title="Create an API key for your app">

Your backend should not hold the `admin` key. An `enroll` key can upsert contacts, enroll them and read what happened, but it cannot change senders or sequences.

```bash
APP_KEY=$(curl -s -X POST $SEQ/v1/api-keys \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"name":"crm-backend","scopes":["enroll"]}' | jq -r .data.api_key)
```

Scopes are ordered `read`, `enroll`, `admin`, and each one can do everything the scopes before it can.

</Step>
<Step title="Add a sender">

A sender is the person the email comes from. You address it by your own id (`u_42` here). Connecting Google gives the sender an `email` channel. With mock providers the channel is active at once; in production the same call returns a consent URL the sender opens once.

```bash
curl -s -X PUT $SEQ/v1/senders/u_42 \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"name":"Max Rivera","email":"max@acme.com","timezone":"America/New_York"}' > /dev/null

curl -s -X POST $SEQ/v1/senders/u_42/connections/google \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" | jq .data.status
# "active"
```

</Step>
<Step title="Add a contact">

A contact is the person who receives the sequence, also addressed by your own id. `attrs` is free JSON that templates and conditions can read.

```bash
curl -s -X PUT $SEQ/v1/contacts/p_7 \
  -H "Authorization: Bearer $APP_KEY" -H "Content-Type: application/json" \
  -d '{"first_name":"Dana","email":"dana@example.com","timezone":"Europe/London","attrs":{"plan":"trial"}}' | jq .data.id
# "ctc_..."
```

</Step>
<Step title="Publish a sequence">

The definition is one JSON document: an email, then a wait of up to three days for a reply. `exit_on` makes a reply end the enrollment.

```bash
cat > definition.json <<'EOF'
{
  "schema_version": 1,
  "entry": "start",
  "exit_on": ["reply"],
  "nodes": {
    "start": { "type": "start", "next": { "then": "intro" } },
    "intro": {
      "type": "outreach", "channel": "email", "action": "send",
      "params": {
        "subject": "Quick question, {{ contact.first_name | \"there\" }}",
        "body": "Hi {{ contact.first_name | \"there\" }}, this is {{ sender.name }}.\n\nUnsubscribe: {{ unsubscribe_url }}"
      },
      "next": { "sent": "wait_reply", "skipped": "end", "failed": "end" }
    },
    "wait_reply": {
      "type": "wait_for",
      "params": { "events": ["reply"], "timeout": "3d" },
      "next": { "reply": "end", "timeout": "end" }
    },
    "end": { "type": "end" }
  }
}
EOF
```

Creating a sequence also creates its first draft version. Save the definition into the draft, then publish it. Publishing fails on validation errors; warnings come back in `problems` and do not block.

```bash
CREATED=$(curl -s -X POST $SEQ/v1/sequences \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" -d '{"name":"Trial intro"}')
SEQ_ID=$(echo $CREATED | jq -r .data.sequence.id)
VER_ID=$(echo $CREATED | jq -r .data.version.id)

curl -s -X PUT $SEQ/v1/sequences/$SEQ_ID/versions/$VER_ID/draft \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d "{\"definition\": $(cat definition.json), \"lock_version\": 0}" | jq .data.problems
# []

curl -s -X POST $SEQ/v1/sequences/$SEQ_ID/versions/$VER_ID/publish \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" | jq .data.version.status
# "published"
```

</Step>
<Step title="Enroll the contact">

Enroll the contact as the sender. A contact can be in one active sequence per project, so enrolling `p_7` a second time returns `409 ALREADY_IN_SEQUENCE`.

```bash
ENR_ID=$(curl -s -X POST $SEQ/v1/sequences/$SEQ_ID/enrollments \
  -H "Authorization: Bearer $APP_KEY" -H "Content-Type: application/json" \
  -d '{"contacts":["p_7"],"sender":"u_42"}' | jq -r '.data.enrollments[0].id')
echo $ENR_ID
# enr_...
```

</Step>
<Step title="Watch the journey and the mock mailbox">

Within about ten seconds the planner picks up the enrollment (it runs every five seconds) and the email worker sends through the mock mailbox. The journey lists every step that ran and every message.

```bash
sleep 10
curl -s $SEQ/v1/enrollments/$ENR_ID -H "Authorization: Bearer $APP_KEY" \
  | jq '{node: .data.enrollment.currentNodeId, runs: [.data.runs[] | "\(.nodeId) \(.status)"], sent: .data.messages[0].subject}'
# { "node": "wait_reply", "runs": ["start done", "intro done", "wait_reply waiting"], "sent": "Quick question, Dana" }
```

The mock mailbox keeps sent mail in memory and has no inbox to open. The contact's timeline shows the message as it went out, with its rendered body and the thread reference a reply is matched on:

```bash
curl -s $SEQ/v1/contacts/p_7/timeline -H "Authorization: Bearer $APP_KEY" \
  | jq '.data[] | select(.kind == "message") | .item | {direction, subject, body, threadRef}'
```

</Step>
<Step title="Simulate a reply">

With mock providers on, `POST /hooks/mock/{project slug}` accepts an inbound event as if Gmail had reported it. Reply in the thread of the email that went out:

```bash
THREAD=$(curl -s $SEQ/v1/enrollments/$ENR_ID -H "Authorization: Bearer $APP_KEY" | jq -r '.data.messages[0].threadRef')

curl -s -X POST $SEQ/hooks/mock/acme -H "Content-Type: application/json" \
  -d "{\"kind\":\"reply\",\"channel\":\"email\",\"externalId\":\"evt_1\",\"from\":\"dana@example.com\",\"to\":\"max@acme.com\",\"threadRef\":\"$THREAD\"}"
# {"ok":true,"stored":1,"ignored":0}

sleep 6
curl -s $SEQ/v1/enrollments/$ENR_ID -H "Authorization: Bearer $APP_KEY" \
  | jq '{status: .data.enrollment.status, reason: .data.enrollment.exitReason}'
# { "status": "exited", "reason": "replied" }

curl -s $SEQ/v1/sequences/$SEQ_ID/analytics/summary -H "Authorization: Bearer $APP_KEY" \
  | jq '{enrolled: .data.enrolled, replies: .data.replies, replies_by_channel: .data.replies_by_channel}'
# { "enrolled": 1, "replies": 1, "replies_by_channel": { "email": 1 } }
```

The reply became a signal, was credited to the `intro` email, and ended the enrollment because `exit_on` lists `reply`.

</Step>
</Steps>

## The same flow in TypeScript

The SDK wraps the same calls. This script does everything above after `docker compose up`, on a fresh database:

```ts title="quickstart.ts"
import { readFileSync } from 'node:fs';
import { OpenSequence, OpenSequenceAdmin } from '@opensequence/sdk';

const baseUrl = 'http://localhost:8080';
const definition = JSON.parse(readFileSync('definition.json', 'utf8'));

const operator = new OpenSequenceAdmin({ baseUrl, adminToken: 'dev-admin-token' });
const { project, api_key } = await operator.projects.create({ slug: 'acme', name: 'Acme' });
const admin = new OpenSequence({ baseUrl, apiKey: api_key });

const appKey = await admin.project.apiKeys.create({ name: 'crm-backend', scopes: ['enroll'] });
const app = new OpenSequence({ baseUrl, apiKey: appKey.api_key });

await admin.senders.upsert('u_42', { name: 'Max Rivera', email: 'max@acme.com', timezone: 'America/New_York' });
await admin.senders.connectGoogle('u_42');
await app.contacts.upsert('p_7', { first_name: 'Dana', email: 'dana@example.com', timezone: 'Europe/London', attrs: { plan: 'trial' } });

const { sequence, version } = await admin.sequences.create({ name: 'Trial intro' });
await admin.sequences.versions.saveDraft(sequence.id, version.id, { definition, lock_version: 0 });
await admin.sequences.versions.publish(sequence.id, version.id);

const { enrollments } = await app.sequences.enroll(sequence.id, { contacts: ['p_7'], sender: 'u_42' });
await new Promise((r) => setTimeout(r, 10_000));

const journey = await app.enrollments.get(enrollments[0].id);
console.log(project.slug, journey.enrollment.currentNodeId, journey.messages[0]?.subject);
// acme wait_reply Quick question, Dana
```

## Clean up

```bash
docker compose down -v
```

`-v` also deletes the Postgres volume. Leave it off to keep your data for next time.
